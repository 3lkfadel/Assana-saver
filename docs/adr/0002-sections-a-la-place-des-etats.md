# Les sections remplacent les états dans l'interface

Plane organise les tâches par **états** configurables (backlog, à faire, en cours, terminé, annulé) qui servent aussi de colonnes Kanban. Asana organise un projet en **sections** libres et ne connaît qu'une complétion binaire (**terminée** ou non). Nous adoptons le modèle Asana : chaque appartenance place la tâche dans une section de son projet, la complétion est une case à cocher, et l'avancement détaillé passe par un champ personnalisé « Statut ». Les états de Plane disparaissent de l'interface ; ils ne doivent pas être réintroduits comme second axe de rangement.

## Options écartées

- **Sections et états côte à côte** : deux axes de rangement concurrents dans chaque vue, source de confusion.
- **Garder les états comme colonnes** : incompatible avec le multi-homing, où une même tâche doit pouvoir occuper une section différente dans chaque projet.
